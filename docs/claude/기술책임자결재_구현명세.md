## 1. 선행 UI 작업 ✅ 전체 완료

### 1-1. reportModify 모달 — 수리/불가/초기화 버튼 추가 ✅

**위치:** 성적서 수정 모달 좌측 하단 '성적서작성' 버튼 우측

| 버튼 | 동작 | 활성색상 | 비활성(NORMAL) 색상 |
|---|---|---|---|
| 수리 | report_status = REPAIR | 하늘색 | 연한 회색(기본) |
| 불가 | report_status = IMPOSSIBLE | 빨간색 | 연한 회색(기본) |
| 초기화 | report_status = NORMAL | 노란색(항상) | — |

- 3개 버튼은 여백 없이 붙여서 표시
- 수리/불가 처리 전 `gMessage()` confirm 필수
- 초기화 클릭 시 수리·불가 버튼 색상 → 기본 회색으로 변경
- 실무자 결재 완료(`work_status = SUCCESS`) 시 수리/불가 버튼 클라이언트 disabled 처리 ✅ (2026-05-01 추가)

**수리/불가 처리 시 초기화 대상 (member_id 제외)**

## 3. 주요 기능 상세

### 3-1. 성적서 반려처리 ✅

**진입 경로:** 좌측 상단 '반려' 버튼(체크 기준) 또는 '결재자' 열의 '반려' 버튼(단건)

**검증 조건 (반려 불가 케이스)**
- approval_status IN ('READY', 'PROGRESS', 'SUCCESS') → 반려 불가

**처리 흐름**
1. 검증 통과 → `reportReject` 모달 호출 (`gModal`, sm 사이즈)
   - 모달 타이틀: 단건 → `성적서번호`, N건 → `성적서 번호 [XXX] 외 N건 반려`
   - 내용: 반려사유 textarea (resize 불가, 기본 6줄)
   - 버튼: '반려'(isConfirmed), '닫기'
   - 반려사유 미입력 시 프론트 검증으로 차단
2. 반려 클릭 → `gLoadingMessage('반려처리중입니다...')` 표시
3. 백엔드 처리:
   - report_status = 'REJECTED'
   - status_remark = 반려사유
   - work_datetime, work_status, approval_datetime, approval_status 초기화
   - file_info (ref_table_name='report', type='signed') → is_visible = 'n'
   - report_job_batch 중 해당 성적서 PROGRESS 상태인 배치 → CANCELED 처리
   - report_job_item 데이터는 이력 보존 (삭제/초기화 안 함)
4. 완료 → 모달 닫힘 + 그리드 재조회 (반려된 성적서는 리스트에서 사라짐)

---

### 3-2. 성적서 결재 (다중결재) ✅ 완료

#### 진입 경로

- 좌측 상단 '다중결재' 버튼 (다건)
- '결재자' 열의 '확인' 버튼 (단건)

#### 검증 조건 (결재 불가 케이스)

- `approval_status IN (READY, PROGRESS, SUCCESS)` → 결재 불가 (중복/완료)
- `approvalMemberId = null` → 결재 불가 (기술책임자 미지정)
- 기술책임자의 서명이미지 파일 미존재 → 결재 불가

#### 결재일자 선택 UI

- SweetAlert2 창에 jQuery UI datepicker 인풋 포함 (기존 의존성, 신규 추가 없음)
- 날짜 형식: `yyyy-mm-dd`
- 날짜 미입력 시 결재 진행 불가 → `gToast()` 경고
- 버튼: '결재'(isConfirmed), '취소'

#### 처리 흐름

1. 결재 대상 검증 → 날짜 선택 SweetAlert2 → '결재' 클릭
2. `gLoadingMessage('결재처리중입니다...')` 표시
3. `POST /api/excelwork/batches/manager-approval` 호출
   - `approval_status = READY` 로 상태 변경, 배치/아이템 생성
4. ExcelWorkApp이 READY 콜백 수신 → 작업 목록 표시, 처리 시작
   - `approval_status = PROGRESS` 전환
5. ExcelWorkApp 처리 (아이템별):
   - `signed_xlsx` 다운로드 (`/api/excelwork/file/{fileUuid}`)
   - 기술책임자 서명이미지 다운로드 (`/api/excelwork/sign-image/member/{approvalMemberId}`)
   - `manager_sign` shape들에 서명이미지 삽입
   - QR코드 이미지 생성 (URL: `{서버주소}/r/{reportId}`) → `qr_code` shape에 삽입
   - '데이터' 시트 E21 셀에 결재일자 삽입 (`yyyy. m. d` 형태)
   - xlsx → pdf 변환
   - signed_xlsx, signed_pdf 스토리지 업로드
6. 완료 콜백 (`POST /api/excelwork/callback/manager-approval-item-done`) → CALI:
   - 기존 signed_xlsx/pdf file_info 소프트삭제 + 신규 FileInfo INSERT
   - `approval_status = SUCCESS`
   - `approval_datetime = 선택한 결재일자 (시분초 없이, 00:00:00 저장)`
7. 전체 완료 후 로딩 닫힘 + 그리드 재조회

#### 백엔드 API

| 항목 | 엔드포인트 | 비고 |
|---|---|---|
| 배치 생성 | `POST /api/excelwork/batches/manager-approval` | Security: ROLE_ADMIN |
| 완료 콜백 | `POST /api/excelwork/callback/manager-approval-item-done` | Security: permitAll (X-Callback-Key 검증) |
| PDF 공개 뷰어 | `GET /r/{reportId}` | Security: permitAll, Content-Type: application/pdf |

#### QR코드 PDF 뷰어 API (`GET /r/{reportId}`)

- Security에서 `/r/**` 경로를 `permitAll`로 오픈
- reportId로 signed_pdf file_info 조회 → NCP 스토리지에서 스트리밍
- Content-Type: `application/pdf` 응답 → 모바일 브라우저 자동 PDF 뷰어 실행
- 로컬/개발: cali-dev 버킷, 운영: cali 버킷 (환경별 자동 분기, 기존 스토리지 설정 활용)
- 추후 비밀번호 입력 방식으로 전환 예정

#### 다중업로드 validate 보완 (mode=manager)

현재 `approval_status = SUCCESS` 검증만 있음 → 아래 추가 검증 필요:
- 파일명(확장자 제외) = `report.reportNum` 매칭 필수
- 동일 업로드 내 xlsx/pdf 혼합 불가
- `approval_status IN (READY, PROGRESS)` → 업로드 불가 (진행 중)
- 검증 실패 파일: invalid 목록에 추가 (전체 중단 아닌 스킵)

### 3-3. 일괄다운로드 (EXCEL / PDF) ✅

**방식:** 서버사이드 ZIP 스트리밍 (`ZipOutputStream`)

- 1건: 단순 파일 다운로드
- N건: 단일 ZIP으로 묶어서 반환 (임시 디스크 파일 미생성 — 스트리밍)
- 진행 표시: 파일 수를 포함한 로딩 스피너 (`N개 파일 ZIP 준비 중...`)

### 3-4. 성적서 취소 ✅

**진입 경로:** 좌측 상단 '일괄취소' 버튼 또는 '취소' 열의 '취소' 버튼(단건)

- 대상: approval_status = SUCCESS인 성적서만
- confirm 후 진행
- 초기화 대상: approval_status → IDLE, approval_datetime → NULL
- 유지 대상: approval_member_id (초기화 안 함)
- 완료 후 그리드 갱신 → '결재자' 열에 '반려'/'확인' 버튼 재표시

### ManagerApprovalJobService 처리 흐름

```
각 item에 대해:
  b. signed.xlsx 다운로드 (item.FileDownloadUrl — 서버 MANAGER_APPROVAL 분기 제공)
  c. 기술책임자 서명 이미지 다운로드 (item.SignImgUrl — per-item)
  d. QRCoder: item.Data["qrCodeUrl"] → PngByteQRCode → PNG 파일 생성
  e. ClosedXML: item.Data["approvalDate"] → SheetSettings["approvalDate"].Cell 삽입
  f. Excel Interop:
     - "manager_sign" 도형에 서명 이미지 삽입
     - "qr_code" 도형에 QR코드 이미지 삽입
     - XLSX → PDF 변환
  g. POST /api/excelwork/callback/manager-approval-item-done (xlsxFile + pdfFile)
  h. 로컬 결과 파일 저장 (GetSignedXlsxPath / GetSignedPdfPath)
```

| `sheetSettings["approvalDate"]` 셀 주소 | 실제 엑셀 템플릿과 맞는지 확인 |
| `"manager_sign"` / `"qr_code"` 도형명 | 실제 엑셀 템플릿의 도형명과 일치 여부 확인 |
| QR코드 크기 (20px per module) | 엑셀 도형 크기와 시각적 적합성 확인 |
