# 기술책임자결재 — 결재 흐름 설명

> 프론트 결재 시작 → 배치 생성 → ExcelWorkApp 처리 → 콜백 → 결재 완료까지 주요 로직 요약  
> 발표 기준 약 5분 분량

---

## 전체 흐름 한눈에 보기

```
[브라우저] 결재일자 선택 + 결재 버튼 클릭
    ↓ POST /api/excelwork/batches/manager-approval
[CALI 서버] 검증 → approvalDatetime 선반영 → Batch/Item 생성 → token 발급
    ↓ excelwork://process?token=...&serverUrl=... (URI 스킴)
[ExcelWorkApp] 잡 JSON 조회 → signed.xlsx 다운로드
             → 기술책임자 서명 삽입 + QR코드 삽입 + 결재일자 삽입
             → PDF 변환
    ↓ POST /api/excelwork/callback/manager-approval-item-done (xlsx + pdf)
[CALI 서버] 파일 저장 → approvalStatus = SUCCESS
    ↓ QR코드 스캔 시
[공개 URL] GET /r/{reportId} → signed.pdf inline 렌더링 (인증 불필요)
```

## 1. 프론트 — 결재 시작 (`managerApproval.js`)

그리드에서 성적서 선택 후 결재 버튼(단건: 확인, 다건: 다중결재) 클릭 시 공통 함수 `doApprove()` 진입.

```javascript
// 단건: ManagerApprovalCellRenderer의 "확인" 버튼
$(document).on('click', '.btn-manager-approve', function () {
    const rowKey = $(this).data('row-key');
    const row = $modal.grid.getRow(rowKey);
    doApprove([row]);
});

// 다건: 그리드 상단 "다중결재" 버튼
$modal.find('.btnMultiApprove').on('click', async function () {
    const checkedRows = $modal.grid.getCheckedRows();
    doApprove(checkedRows);
});

async function doApprove(rows) {
    // 이미 결재 진행 중/완료인 성적서 차단
    const blocked = rows.filter(r => ['READY', 'PROGRESS', 'SUCCESS'].includes(r.approvalStatus));
    if (blocked.length > 0) {
        await gMessage('결재 불가', `아래 성적서는 결재가 진행 중이거나 완료되었습니다:<br>${nums}`, 'warning', 'alert');
        return;
    }

    // SweetAlert2 + jQuery UI datepicker로 결재일자 입력
    const { isConfirmed, value: approvalDate } = await Swal.fire({
        title: '결재일자 선택',
        html: '<input type="text" id="swalApprovalDate" class="swal2-input" readonly>',
        didOpen: () => {
            $('#swalApprovalDate').datepicker({
                dateFormat: 'yy-mm-dd',
                // SweetAlert2 위에 datepicker가 표시되도록 z-index 조정
                beforeShow: (input, inst) => {
                    setTimeout(() => { inst.dpDiv.css('z-index', 99999); }, 0);
                },
            });
        },
        preConfirm: () => {
            const date = $('#swalApprovalDate').val().trim();
            if (!date) { Swal.showValidationMessage('결재일자를 선택해주세요.'); return false; }
            return date;
        },
    });
    if (!isConfirmed) return;

    // 배치 생성 요청 → excelworkUri 실행
    const res = await fetch('/api/excelwork/batches/manager-approval', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json; charset=utf-8' },
        body: JSON.stringify({ reportIds, approvalDate }),
    });
    const data = await res.json();
    if (data?.code > 0) {
        window.location.href = data.data?.excelworkUri;  // ExcelWorkApp 실행
    }
}
```

## 2. 백엔드 — 배치 생성 (`ExcelWorkServiceImpl.createManagerApprovalJob`)

`POST /api/excelwork/batches/manager-approval` 요청을 받아 아래 순서로 처리.

```java
@Transactional
public ExcelWorkDTO.CreateJobRes createManagerApprovalJob(
        ExcelWorkDTO.CreateManagerApprovalJobReq req, Long memberId) {

    // ── 1. 유효성 검증 ──────────────────────────────────────────────────────
    for (Report report : reports) {
        if (report.getWorkStatus() != AppStatus.SUCCESS)         // 실무자결재 완료 필수
            throw new IllegalArgumentException("실무자결재가 완료되지 않은 성적서입니다.");
        if (report.getApprovalStatus() == AppStatus.READY
         || report.getApprovalStatus() == AppStatus.PROGRESS
         || report.getApprovalStatus() == AppStatus.SUCCESS)     // 중복 결재 차단
            throw new IllegalArgumentException("이미 기술책임자결재가 진행 중이거나 완료된 성적서입니다.");
        if (report.getApprovalMemberId() == null)                // 기술책임자 미지정 차단
            throw new IllegalArgumentException("기술책임자가 지정되지 않은 성적서입니다.");
        approvalMemberIds.add(report.getApprovalMemberId());
    }
    // 기술책임자 서명 이미지 존재 확인 (등록되지 않으면 차단)
    // ...

    // ── 2. 결재일자 선반영 ───────────────────────────────────────────────────
    // DB 스키마 변경 없이 기존 approval_datetime 컬럼을 배치 시작 전에 미리 저장.
    // ExcelWorkApp이 잡 JSON에서 approvalDate를 읽어 셀에 삽입하고,
    // 콜백(callbackManagerApprovalItemDone) 시에는 approvalStatus=SUCCESS만 업데이트.
    LocalDateTime approvalDatetime = LocalDate.parse(req.getApprovalDate()).atStartOfDay();
    reports.forEach(r -> {
        r.setApprovalDatetime(approvalDatetime);    // 결재일자 선반영
        r.setApprovalStatus(AppStatus.READY);
        r.setApprovalMemberId(memberId);            // 요청자(기술책임자 본인)로 갱신
    });

    // ── 3. Batch + Item 생성 ─────────────────────────────────────────────────
    String token = UUID.randomUUID().toString().replace("-", "");  // 32자 hex
    ReportJobBatch batch = batchRepository.save(ReportJobBatch.builder()
            .jobType(JobType.MANAGER_APPROVAL)
            .token(token)
            .totalCount(reportIds.size())
            .status(BatchStatus.READY)
            .build());

    // 성적서 1건당 Item 1개, fileUuid로 파일 on-demand 다운로드에 사용
    List<ReportJobItem> items = reportIds.stream()
            .map(reportId -> ReportJobItem.builder()
                    .batchId(batch.getId())
                    .reportId(reportId)
                    .fileUuid(UUID.randomUUID().toString())  // 파일 다운로드 식별자
                    .build())
            .collect(Collectors.toList());
    itemRepository.saveAll(items);

    // ── 4. excelwork:// URI 반환 ─────────────────────────────────────────────
    String excelworkUri = "excelwork://process?token=" + token
            + "&serverUrl=" + URLEncoder.encode(serverUrl, StandardCharsets.UTF_8)
            + "&callbackKey=" + URLEncoder.encode(excelworkCallbackKey, StandardCharsets.UTF_8);

    return new ExcelWorkDTO.CreateJobRes(batch.getId(), token, excelworkUri, reportIds.size());
}
```

## 3. ExcelWorkApp — 잡 조회 및 파일 처리

브라우저가 `excelwork://` URI를 실행하면 로컬 설치된 ExcelWorkApp이 기동.  
아래 순서로 CALI 서버와 통신하며 성적서를 처리한다.

### 3-1. 잡 JSON 조회 (`GET /api/excelwork/job/{token}`)

CALI 서버의 `getJobByToken()`이 MANAGER_APPROVAL에 대해 아래 정보를 반환.

```java
// item별 signImgUrl: 기술책임자 서명 이미지 (approvalMemberId 기반)

// data 맵: MANAGER_APPROVAL 전용 필드 추가

data.put("qrCodeUrl",    base + "/r/" + report.getId());                          // QR코드 대상 URL
```

### 3-3. ExcelWorkApp 내부 처리 (`ManagerApprovalJobService`)

`MainViewModel.HandleUri()`가 `action == "manager_approval"`을 감지하면 STA 스레드에서 `ManagerApprovalJobService.ProcessAsync()` 호출.  
각 item에 대해 아래 순서로 처리한다.

```csharp
// ManagerApprovalJobService.ProcessAsync() — 핵심 흐름

// b. signed.xlsx 다운로드 (서버가 MANAGER_APPROVAL 분기에서 signed.xlsx 제공)
await callback.DownloadFileAsync(item.FileDownloadUrl, tempXlsxPath);

// c. 기술책임자 서명 이미지 다운로드 (per-item — 기술책임자가 item별로 다를 수 있음)
//    WORK_APPROVAL: job.SignImgUrl(job 단위 1회)
//    MANAGER_APPROVAL: item.SignImgUrl(per-item, approvalMemberId 기반)
await callback.DownloadFileAsync(item.SignImgUrl, signImgPath);

// d. QR코드 PNG 생성 (QRCoder 라이브러리)
//    item.Data["qrCodeUrl"] = "https://cali.example.com/r/{reportId}"
using var qrGenerator = new QRCodeGenerator();
var qrData = qrGenerator.CreateQrCode(qrCodeUrl, QRCodeGenerator.ECCLevel.M);
var bytes  = new PngByteQRCode(qrData).GetGraphic(20);  // 20px per module
File.WriteAllBytes(qrImgPath, bytes);

// e. 결재일자 셀 삽입 (ClosedXML — Interop 이전 단계)
//    item.Data["approvalDate"] = "2026-05-01"
//    job.SheetSettings["approvalDate"].Cell = "E21", Format = "yyyy. m. d"
using var workbook = new XLWorkbook(xlsxPath);
foreach (var ws in workbook.Worksheets)
    ws.Cell(cellAddress).Value = formatted;   // "2026. 5. 1"
workbook.Save();

// f. Excel Interop: 도형에 이미지 삽입 + PDF 변환
//    SignSheetNames: 성적서(갑)(영문) / 성적서(을)(영문) / 성적서(갑)(국문) / 성적서(을)(국문)
shapes.Item("manager_sign").Fill.UserPicture(signImgPath);  // 서명
shapes.Item("qr_code").Fill.UserPicture(qrImgPath);         // QR코드
workbook.ExportAsFixedFormat(xlTypePDF, pdfPath, ...);

// g. 결과 업로드
await callback.SendManagerApprovalItemDoneAsync(token, item.ItemId, tempXlsxPath, tempPdfPath);
//   → POST /api/excelwork/callback/manager-approval-item-done?token=...&itemId=...
//   multipart: xlsxFile + pdfFile
```

**WorkApprovalJobService와의 주요 차이점:**

| 항목 | WorkApproval | ManagerApproval |
|---|---|---|
| 서명 이미지 단위 | job 단위 1회 다운로드 | per-item 다운로드 |
| 서명 도형명 | `writer_sign` | `manager_sign` |
| QR코드 삽입 | 없음 | `qr_code` 도형에 삽입 |
| 결재일자 삽입 | 없음 | ClosedXML로 셀 삽입 |
| 콜백 엔드포인트 | `/callback/approval-item-done` | `/callback/manager-approval-item-done` |

## 4. 백엔드 — 콜백 처리 (`callbackManagerApprovalItemDone`)

ExcelWorkApp이 성적서 1건 처리를 완료할 때마다 호출.

```java
@Transactional
public void callbackManagerApprovalItemDone(
        String token, Long itemId, MultipartFile xlsxFile, MultipartFile pdfFile) {

    // MANAGER_APPROVAL 타입 검증
    if (batch.getJobType() != JobType.MANAGER_APPROVAL)
        throw new IllegalArgumentException("MANAGER_APPROVAL 배치가 아닙니다.");

    // 기존 signed 파일 file_info 소프트삭제 (재결재 등 중복 방지)
    fileInfoRepository.softDeleteByRefAndNames(
            "report", report.getId(),
            List.of("signed_xlsx", "signed_pdf"), YnType.n, now, memberId);

    // signed.xlsx 스토리지 업로드
    // → {rootDir}/report/{reportId}/signed.xlsx
    ncloudS3Client.putObject(PutObjectRequest.builder()
            .bucket(bucket).key(xlsxKey).contentType(CT_XLSX).build(),
            RequestBody.fromInputStream(xlsxFile.getInputStream(), xlsxFile.getSize()));

    // signed.pdf 스토리지 업로드
    // → {rootDir}/report/{reportId}/signed.pdf
    ncloudS3Client.putObject(PutObjectRequest.builder()
            .bucket(bucket).key(pdfKey).contentType(CT_PDF).build(),
            RequestBody.fromInputStream(pdfFile.getInputStream(), pdfFile.getSize()));

    // file_info 2건 신규 등록 (name: "signed_xlsx", "signed_pdf")
    fileInfoRepository.save(FileInfo.builder()... .name("signed_xlsx")...build());
    fileInfoRepository.save(FileInfo.builder()... .name("signed_pdf") ...build());

    // 성적서 상태 갱신
    report.setApprovalStatus(AppStatus.SUCCESS);
    // approvalDatetime은 배치 생성 시 이미 선반영 → 갱신하지 않음

    // Batch 전체 완료 여부 확인 (마지막 item이면 batch finalize)
    if (batch.getSuccessCount() + batch.getFailCount() >= batch.getTotalCount()) {
        finalizeBatch(batch);  // batch.status → SUCCESS/FAIL
    }
}
```

## 5. 결재 완료 후 — QR코드 공개 PDF 열람

결재 완료된 성적서 PDF에 삽입된 QR코드를 스캔하면 아래 공개 엔드포인트에 접근.

```java
// PublicReportController — 인증 불필요 (SecurityConfig: "/r/**" permitAll)
@GetMapping("/{reportId}")
public void streamSignedPdf(@PathVariable Long reportId, HttpServletResponse response) {
    String objectKey = rootDir + "/report/" + reportId + "/signed.pdf";
    // 스토리지에서 읽어 브라우저에 inline 스트리밍
    response.setContentType("application/pdf");
    response.setHeader("Content-Disposition", "inline; filename=\"signed.pdf\"");
    // ...
}
```

QR코드 URL 형식: `{serverUrl}/r/{reportId}` (ex: `https://cali.example.com/r/42`)

## Batch / JobItem 분리 이유

| 개념 | 역할 |
|---|---|
| `ReportJobBatch` | **작업 묶음** — 1회 결재 요청 전체를 대표. token, 총 건수, 전체 상태(READY/PROGRESS/SUCCESS/FAIL) 관리 |
| `ReportJobItem` | **성적서 1건** — fileUuid, 처리 상태, 시작/종료 시각을 건별 관리 |

**분리 이유:**

1. **N건 부분 성공 표현**: "5건 중 3건 성공, 2건 실패"를 표현하려면 Item 단위 상태가 필요. Batch에는 `successCount`, `failCount`만 집계.

2. **파일 on-demand 식별**: ExcelWorkApp이 `fileUuid` 기반으로 파일을 1건씩 요청. Item마다 UUID를 부여해야 서버가 "어떤 성적서의 파일인지" 파악 가능.

3. **콜백 매핑**: `item-done` 콜백이 `itemId` 단위로 오기 때문에 Batch ↔ Item 구조가 없으면 정확한 성적서 매핑 불가.

4. **복구 용이성**: 비정상 종료 시 Item 상태를 보고 어느 성적서까지 처리됐는지 파악 → 스마트 복구(`/api/excelwork/smart-recover`) 기반.
